Есть три пути. Первый — для всех, второй — если хотите автодеплой при каждом `git push`,
третий — для тех, кто хочет понимать, что происходит внутри.

## Путь 1: через агента

Нужно: работающий локально бот (`just dev-d`), 5–10 минут и банковская карта для аренды сервера.

### Шаг 1. Арендовать сервер

Если сервера ещё нет:

```bash
just rent-server            # список провайдеров
just rent-server vdska      # открыть страницу выбранного провайдера в браузере
```

Ссылки партнёрские: автор шаблона получает вознаграждение, цена для вас не меняется.
Список и ссылки лежат в `scripts/providers.py`.

На сайте провайдера создайте сервер: **Ubuntu 22.04 или новее**, минимальный тариф (1 ГБ RAM достаточно).
Провайдер пришлёт письмо с **IP-адресом** и **паролем root**. Они понадобятся на следующем шаге.

### Шаг 2. Подключить сервер

```bash
just venv          # один раз: локальное окружение с библиотекой для SSH
just set-server    # откроется страница в браузере
```

На странице три поля: адрес, пользователь (оставьте `root`) и пароль. Вставьте данные из письма и нажмите
«Подключить». Можно вместо пароля вставить приватный ключ, если провайдер выдал ключ.

Что происходит под капотом: скрипт один раз входит по паролю, создаёт свой SSH-ключ в папке `.deploy/`
и добавляет его на сервер. Пароль нигде не сохраняется. Дальше все команды ходят по ключу.
Папка `.deploy/` в `.gitignore` и запрещена к чтению агенту.

В терминале появится: `✅ Сервер root@123.45.•.• подключён (вход по ключу)`.
Адрес показывается под маской намеренно: он не должен попадать в чат.

### Шаг 3. Задеплоить

```bash
just deploy
```

Скрипт поставит Docker на сервер (если его нет), загрузит файлы проекта и `.env.prod`, соберёт и запустит
контейнеры, проверит их здоровье. `.env.prod` уже готов: его создал `just init`, токен в него записал `just set-token`.

Проверка:

```bash
just server-logs 30     # ищите строку "Bot @имя started successfully"
just server-status      # статус контейнеров
```

Отправьте боту `/start` в Telegram. Обновить бота после изменений — снова `just deploy`.

## Путь 2: автодеплой через GitHub Actions

После пути 1 можно сделать так, чтобы каждый `git push` в ветку `main` сам обновлял бота на сервере.
Секреты в GitHub публикует команда, вручную ничего копировать не нужно.

Нужно: репозиторий проекта на GitHub (`git remote -v` показывает origin) и установленный
[GitHub CLI](https://cli.github.com): `brew install gh` (macOS), `winget install GitHub.cli` (Windows),
`sudo apt install gh` (Ubuntu).

```bash
gh auth login        # один раз, в терминале: откроется браузер
just deploy-github   # запишет секреты SERVER_HOST, SERVER_PORT, SERVER_USER, SSH_PRIVATE_KEY, PROJECT_PATH, ENV_PROD
git push origin main # проверка: вкладка Actions в репозитории
```

Workflow `.github/workflows/deploy.yml` сначала прогоняет линтер и тесты, затем запускает тот же скрипт,
что и `just deploy`, только с раннера GitHub. Если секреты не заданы, деплой пропускается, проверки идут.

Изменили токен или `.env.prod`? Повторите `just deploy-github`.

## Путь 3: вручную на сервере

Для тех, кто хочет всё сделать сам и понимать каждый шаг. Результат тот же, что у пути 1.

### Подключение к серверу

macOS / Linux — терминал:

```bash
ssh root@ВАШ_IP_АДРЕС
```

Windows — [PuTTY](https://www.putty.org/): Host Name = IP-адрес, логин `root`, пароль из письма
(символы при вводе не отображаются — это нормально).

### Установка Docker

```bash
curl -fsSL https://get.docker.com | sh
docker --version
docker compose version
```

### Пользователь deploy (по желанию, для безопасности)

```bash
adduser deploy                 # придумайте пароль, остальные поля — Enter
usermod -aG docker,sudo deploy
su - deploy
```

### Проект на сервере

```bash
sudo apt install -y git
cd ~
git clone https://github.com/ВАШ_USERNAME/ВАШ_РЕПОЗИТОРИЙ.git
cd ВАШ_РЕПОЗИТОРИЙ
```

`.env.prod` проще всего скопировать с локальной машины, там он уже заполнен:

```bash
# на локальной машине
scp .env.prod root@ВАШ_IP_АДРЕС:~/ВАШ_РЕПОЗИТОРИЙ/.env.prod
```

Или создать на сервере из шаблона и заполнить в редакторе:

```bash
cp .env.prod.example .env.prod
nano .env.prod       # BOT_TOKEN, BOT_USERNAME, ADMIN_USERNAMES, POSTGRES_PASSWORD, REDIS_PASSWORD
                     # сохранить: Ctrl+X, затем Y, затем Enter
```

### Запуск

```bash
python3 scripts/deploy.py      # сборка, запуск, проверка здоровья
docker compose -f docker-compose.prod.yml ps
docker compose -f docker-compose.prod.yml logs --tail=50 bot
```

### SSH-ключ вместо пароля

Так делает `just set-server`; вручную это выглядит так (на локальной машине):

```bash
ssh-keygen -t ed25519 -f ~/.ssh/bot_deploy -N ""
ssh-copy-id -i ~/.ssh/bot_deploy.pub root@ВАШ_IP_АДРЕС
ssh -i ~/.ssh/bot_deploy root@ВАШ_IP_АДРЕС   # вход без пароля
```

Чтобы `just deploy` использовал этот ключ: `just set-server --host ВАШ_IP_АДРЕС --key-file ~/.ssh/bot_deploy`.

### Секреты GitHub Actions вручную

Репозиторий на GitHub → **Settings → Secrets and variables → Actions → New repository secret**:

| Имя | Значение |
|---|---|
| `SERVER_HOST` | IP-адрес сервера |
| `SERVER_PORT` | `22` |
| `SERVER_USER` | `root` или `deploy` |
| `SSH_PRIVATE_KEY` | содержимое приватного ключа целиком (от `-----BEGIN` до `-----END`) |
| `PROJECT_PATH` | папка проекта на сервере, например `/root/my_bot` |
| `ENV_PROD` | содержимое файла `.env.prod` целиком |

## Частые проблемы

### «Нет библиотеки paramiko»

`just venv`, затем повторите команду. Библиотека для SSH ставится в локальное окружение `.venv`.

### «Сервер не принял пароль или ключ»

Проверьте пользователя (обычно `root`) и пароль из письма провайдера: копируйте его целиком, без пробелов.
Если сервер переустанавливали — ключ на нём пропал, повторите `just set-server`.

### «Не удалось подключиться … TimeoutError»

Сервер ещё не поднялся (подождите 1–2 минуты после создания) или порт SSH закрыт файрволом провайдера.
В панели провайдера проверьте, что порт 22 открыт.

### Бот не отвечает после деплоя

```bash
just server-logs 100      # ищите строки с ERROR
just doctor               # локально: токен, админы, сервер
```

Частая причина — в `.env.prod` нет токена: `just set-token` записывает его в оба файла, затем `just deploy`.

### «CHANGE_ME» в логах деплоя

В `.env.prod` остались пароли-заглушки. `just init <имя> @username` генерирует настоящие; затем `just deploy`.

### Пароль сервера попал в чат с агентом

Смените пароль в панели провайдера. Ключ из `.deploy/` продолжит работать, деплой не сломается.

### Docker-команды на сервере требуют sudo

```bash
usermod -aG docker deploy     # под root, затем перелогиньтесь под deploy
```

### Как посмотреть логи GitHub Actions

Репозиторий → вкладка **Actions** → нужный запуск → job **Deploy Bot** → разверните шаги.
